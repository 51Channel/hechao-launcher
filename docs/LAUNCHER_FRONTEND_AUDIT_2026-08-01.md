# 启动器前端与业务逻辑审查

> 审查日期：`2026-08-01`
>
> 审查对象：`src/Hechao.Launcher`、启动器目录契约及相关 API 目录字段
>
> 状态：候选改动已完成验证，尚未发布安装包、OSS 版本或生产 API

## 1. 审查方法

本轮同时使用 `impeccable` 的原生应用审查、加固和无障碍检查方法，以及
`taste-skill` 的密度、层级、对齐和反模板化检查方法。启动器属于高频工具型桌面应用，
本轮保持现有视觉方向，重点提升扫描效率、状态可辨识度和操作结果的确定性，不做品牌重设计。

审查覆盖：

- `1500 x 860` 常规窗口与 `1060 x 640` 最小支持窗口。
- 服务器、活动、下载、账户、设置及设置页底部区域。
- Microsoft 登录、自更新、安装阶段、Toast、键盘焦点和长路径显示。
- 安装、修复、删除、启动、切服、目录切换、活动排期和共享玩家设置的异步边界。
- 新旧目录缓存兼容、失败恢复和同版本自更新失败后的重试行为。

## 2. 主要问题与修复

### 2.1 高风险业务逻辑

| 问题 | 风险 | 处理结果 |
| --- | --- | --- |
| 长任务读取可变的当前服务器、目录、Java 和内存状态 | 操作期间切页或切目录可能安装、删除或启动错误档案 | 操作开始时冻结完整上下文；安装、删除和游戏运行期间禁止破坏上下文的切换与重置 |
| 目录或状态请求晚返回 | 旧目录结果可能覆盖新目录 UI，甚至误报已安装状态 | 目录加载和客户端状态检查均加入 generation、取消令牌及账号/目录快照校验 |
| 游戏退出事件缺少真实数据根目录 | 切换数据目录后可能从错误档案回收 `options.txt` | 运行状态与退出事件携带真实 `DataRoot`，切服前和退出后均从实际运行目录同步 |
| 活动进服依赖已加载目录 | 排期或维护状态变化后仍可能使用陈旧入口 | 进入活动服前重新读取权威目录；关闭或维护时允许预装，但禁止进服 |
| 活动分区依赖展示分类字符串 | 服务名称或旧缓存格式变化会造成活动页空白或错分 | API 增加 `ServerCatalogSection`；旧缓存缺字段时保留兼容分类规则 |

### 2.2 稳定性与兼容性

- 活动排期使用本地时间展示，并在开放、关闭边界自动刷新；超过 .NET 单次延时上限的排期按
  30 天分段等待，避免约 49.7 天后的计时溢出。
- 自更新安装失败会保留当前版本和手动重试入口；启动时不会对同一个失败版本形成重启循环。
- 下载历史写盘失败不再破坏已经完成的安装清理流程。
- 同服务器切换数据目录时，旧目录的状态请求不能回写新目录。
- 活动列表使用独立 ViewModel 维护公告、排期和下一次状态转换，避免在 XAML 中复制业务判断。

### 2.3 布局与无障碍

- 修复设置页行越界、详情内容无法滚动、最小窗口标题栏按钮和长游戏目录挤压布局的问题。
- 长路径改为右侧省略并提供完整路径 Tooltip，动态内容不再改变固定控制区尺寸。
- Microsoft 登录和更新遮罩移动到全局层；打开时获取键盘焦点，关闭后恢复原焦点。
- Toast 区分信息、成功和错误，使用动态图标并通过 UI Automation live region 公告。
- 安装四阶段增加当前点、完成勾和失败叉，同时提供中文自动化状态，不再只依赖颜色。
- 补齐焦点环对比度、状态点语义、缓存文案及八个开关的自动化名称。

## 3. 页面与流程结论

| 页面或流程 | 结论 | 说明 |
| --- | --- | --- |
| 服务器 | 合理 | 主操作、安装状态、人数和版本层级清楚；长任务期间选择状态稳定 |
| 活动 | 合理 | 活动与常驻服显式分区，公告、排期、维护和关闭状态具备完整进服规则 |
| 下载 | 合理 | 进度、失败和重试状态明确；历史持久化失败不会反向破坏安装 |
| 账户 | 合理 | 登录遮罩处于全局层，键盘焦点不会落到遮罩后的页面 |
| 设置 | 合理 | 最小窗口可滚动，开关、路径、Java、内存和目录操作具备明确禁用条件 |
| 安装/修复/删除 | 完整 | 使用档案锁和冻结上下文；删除不触碰共享对象、共享设置或其他档案 |
| 启动/切服/退出 | 完整 | 进入前重新校验目录与授权，玩家设置以真实运行目录为准同步 |
| 自更新 | 完整 | 自动检查、失败保留、同版本防循环和手动重试均有契约覆盖 |
