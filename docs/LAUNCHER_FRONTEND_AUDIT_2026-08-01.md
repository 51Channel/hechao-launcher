# 赫朝启动器前端与业务逻辑审查

> 审查日期：2026-08-01
> 审查基线：`0e1bd07` 之后的本地候选
> 来源：Codex 当前任务
> 结论可信度：高（代码审查、自动化测试、运行态目视验收）

## 1. 审查范围

- 使用 `pbakaus/impeccable` 与 `Leonxlnx/taste-skill` 检查 WPF 启动器的信息层级、布局、交互反馈、可访问性和业务闭环。
- 页面范围：服务器、下载、活动、账户、设置、通知面板、Toast、登录遮罩和启动器更新遮罩。
- 业务范围：目录刷新、安装/修复/删除、启动/切服、活动服开放边界、玩家设置同步、自更新、退出保护和异常恢复。
- 本轮未发布安装包、未上传 OSS、未部署 API，也未启停 Minecraft 服务端。

## 2. 总体结论

当前页面结构适合服务器登录器：左侧主导航稳定，服务器页保持目录与详情的主从关系，功能页具备独立滚动和明确的空闲、加载、失败及过期状态。`1500 x 860` 与最小窗口 `1060 x 640` 下未发现文字重叠、不可恢复的裁切或操作区溢出。

业务主链路已形成闭环，长任务会冻结操作上下文，旧请求不能覆盖新状态，活动服在进入前会复查权威目录，自更新会避让客户端操作和正在运行的游戏。候选可以进入小规模测试，但公开分发前仍建议完成一次 Narrator 和多 DPI 人工验收。

## 3. 本轮修复

### 3.1 布局与交互

- 左侧导航改为真正的 `ToggleButton`，使用 `TwoWay` 绑定，并由 `ActivePage` 保证始终只有一个页面处于选中状态。
- 服务器目录增加加载、错误、缓存过期、内置应急目录和空目录状态，并提供可重试入口。
- 登录与注册提交期间禁用重复操作，验证码冷却由 ViewModel 管理。
- 通知面板具备开关语义、焦点圈定、`Esc` 关闭和关闭后焦点恢复。
- Toast 限制最大宽度并允许换行；目录和 Java 路径使用省略、Tooltip 与辅助说明展示完整值。
- 更新遮罩使用稳定网格行、独立进度区和明确的手动/自动更新状态。
- 修复通知 `ToggleButton` 错用 `Button` 样式导致启动器运行时直接崩溃的问题，并新增样式类型契约测试。

### 3.2 可访问性

- 图标按钮、导航、开关、列表、输入框、密码框、下拉框和进度条补齐稳定的 UIA 名称。
- 服务器、下载历史和活动列表项分别暴露名称、状态与辅助说明。
- 账户消息、目录状态、活动状态、更新进度和 Toast 使用真实 `LiveRegionBorder`。
- Microsoft 正版绑定按钮补充明确名称，避免组合内容被读成空值或控件类型。
- 增加导航 `TwoWay`、列表标签、按钮标签和 `Button`/`ToggleButton` 样式类型契约测试。

### 3.3 业务逻辑

| 问题 | 风险 | 处理结果 |
| --- | --- | --- |
| 长任务读取可变的当前选择 | 安装、删除或启动错误档案 | 操作开始时冻结服务器、档案、目录、Java 和内存上下文；任务期间禁止破坏上下文的切换 |
| 目录或状态请求晚返回 | 旧数据覆盖新 UI | 目录、客户端状态和启动器更新检查均加入 generation、取消令牌与账号/目录快照校验 |
| 同一服务器的档案版本或哈希变化 | 旧客户端仍显示“已就绪”或卡在不可操作状态 | 档案变化时失效旧状态，刷新元数据并立即重新检查本地客户端 |
| 活动开放状态在目录加载后变化 | 已关闭或维护的活动仍可进入 | 主操作前重新读取权威目录；关闭或维护时允许预装但禁止启动 |
| 缓存或内置目录回退后不恢复 | 玩家长期停留在旧状态 | 受控延时自动重试，实时目录恢复后取消重试 |
| 并发更新检查与客户端任务冲突 | 旧版本遮罩覆盖新版本，或更新器中断安装/游戏 | 旧响应失效；安装、修复、回滚、启动和游戏运行期间延期呈现与安装更新 |
| 遥测网络任务不结束 | 安装或启动永久显示忙碌 | 业务状态先完成，遥测后台执行并带超时 |
| 更新器启动失败后重复自动更新 | 形成重启循环 | 下载前清理旧状态，启动更新器前写入持久 attempt 标记；读取失败时按失败关闭，仅允许手动重试 |
| 多个启动器同时写运行状态与共享设置 | 文件竞争和状态错乱 | 应用入口增加命名 Mutex 单实例保护，异常退出后的 abandoned mutex 可恢复 |
| 关键任务期间直接关闭窗口 | 安装或更新状态损坏 | 关键操作期间阻止关闭；仅更新器拥有关闭权时允许退出 |

## 4. 页面结论

| 页面 | 结论 | 说明 |
| --- | --- | --- |
| 服务器 | 合理 | 左侧目录支持扫描，右侧详情、客户端准备和运行配置层级清楚；最小窗口使用纵向滚动 |
| 下载 | 合理 | 活跃任务、空状态和历史记录分区明确，速度、进度、版本、时间与结果可扫描 |
| 活动 | 合理 | 最小窗口保持双列卡片并可纵向滚动；公告、排期、人数、版本和进入条件完整 |
| 账户 | 合理 | 赫朝账号、Microsoft 正版身份与 LuckPerms 权限职责分开，登录和绑定错误不会使程序退出 |
| 设置 | 合理 | 内存、目录、更新、缓存、代理、Java 和账号入口具备明确分组与禁用条件 |
| 通知与全局遮罩 | 合理 | 面板不会超出最小窗口；`Esc` 可关闭并恢复焦点，更新和登录遮罩不会把焦点留在背景页 |

## 6. 剩余风险

- 当前桌面自动化后端未返回 WPF UIA 树；本轮以静态契约和 `LiveRegionBorder` AutomationPeer 单元测试覆盖。公开分发前应使用 Windows Narrator 完成一次键盘全流程人工验收。
- 尚未逐项验证 Windows `125%`、`150%`、`200%` 缩放、高对比度和超长本地化文本。
- 本轮没有执行真实客户端下载、游戏启动、切服或自更新安装，以免改变生产账号、客户端和服务端状态；这些仍由小规模灰度验收承担。
- `MinecraftRunningStateStore` 与 `PlayerGameSettingsService` 本身没有独立的跨进程文件锁。启动器单实例已覆盖当前调用路径；若未来被独立工具或更新器直接复用，应在服务层增加文件锁与原子替换测试。
