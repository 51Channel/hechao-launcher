# 活动企划日历与单活动槽运维手册

> 正式版本：Launcher API `0.30.6`、owl5 ServerControlAgent `0.5.0`
>
> 当前状态：已于 2026-08-14 上线旧目录排期只读显示；迁移 `028` 为 `28/28`，官网桥接已启用，当前
> 正式企划数为 `0`，后台会显示 `赫朝商务追杀` 旧排期及其缺失项；任何活动
> 发布或部署前仍要重新核对代理、活动槽和当前玩家状态。

本功能把整合包、活动排期、玩家下载、活动槽部署和进服准入收敛到一条链路。Launcher
后台和官网后台只是两个管理入口，企划数据只保存在 Launcher PostgreSQL，不在网站
SQLite 中复制。

## 1. 唯一规则

- 可以提前建立多条草稿，也可以提前发布多条未来企划。
- 可以同时保留多条 `Published` 企划，但它们的开放区间不能重叠；任一时间点最多只有
  一条已发布企划处于开放窗口。草稿可以重叠，但重叠草稿不能发布。
- 排期使用半开区间 `[开始, 结束)`。上一场在 `20:00` 结束时，下一场可以从
  `20:00` 开始，不算冲突。
- PostgreSQL 的 GiST 排斥约束是最终门禁；API 在发布和移动已发布企划时先返回可读的
  `409 schedule_conflict`。并发请求即使越过预检查，数据库仍会拒绝重叠。
- 所有企划共享 `activity / owl5 / 127.0.0.1:25568 / owl5-activity-slot`。企划排期
  唯一和物理活动槽唯一是同一业务约束的两个层面。
- 整合包导入页可以创建和选择 `activity-*` 动态部署槽，但当前活动企划仍默认使用固定
  `activity`。动态槽不自动进入企划、官网日历、玩家目录或 Velocity 准入；若未来需要
  企划选择动态槽，必须另行扩展企划数据合同、双后台和准入校验，不能只改部署目标。

## 2. 完整工作流

1. 在 Launcher 后台“整合包导入”上传 ZIP 或 MRPACK，完成自动识别与人工复核。
2. 默认选择“仅发布并入库”。客户端进入 `Test`，服务端制品保留在 API 受限存储中，
   不覆盖活动槽，也不启动 Minecraft。
3. 完成客户端和服务端测试后，在客户端档案后台把该精确清单推进到 `Production`。
   未进入 `Production`、已暂停或档案已归档的整合包不能发布企划。
4. 在任一后台的“活动企划”月历点击日期或框选日期范围，创建草稿并绑定已完成整合包。
5. 调整开放与结束时间。拖动改变整个区间，拖动两端改变开始或结束；草稿重叠只警告。
6. 发布企划。发布后同一数据会出现在 Launcher 活动页、官网社区日历和 ICS。官网只
   展示企划时间与公开信息；玩家必须进入 Launcher 活动页下载或更新绑定客户端。开放前
   目录状态保持 `Closed`，不能取得有效进服授权。
7. 活动槽停服且代理在线时，使用精确确认 `DEPLOY <planId>` 部署企划整合包。部署完成
   后仍保持停服，心跳会上报实际部署的 import、档案和版本身份。
8. 在开放窗口前由管理员按现有服控流程启动活动服。只有当前时间进入排期、服务端在线、
   代理心跳新鲜且活动槽部署身份与企划绑定整合包完全一致时，目录与 Velocity 才允许进入。
9. 活动结束时目录自动关闭准入；Minecraft 进程不会被日历自动停止，管理员仍按服控
   流程安全停服。需要改期时先保证新的已发布区间不与其他企划重叠。

“立即部署活动槽”只用于兼容旧导入流程。新企划应优先使用“仅发布并入库”，随后从
企划日历选择整合包并执行受控部署。

## 3. 四个入口如何同步

- Launcher 活动页读取同一 API 目录；打开页面时立即刷新，停留期间每 30 秒刷新，离开
  页面后停止轮询。客户端下载、更新和本地安装状态只存在于 Launcher。
- Launcher 后台直接调用 `/v1/admin/activity-plans`，每 5 秒刷新。
- 官网后台 `/admin/activity-plans` 只调用同站 `/api/admin/activity-plans`；Next.js
  BFF 再从回环地址调用 `/v1/internal/website/activity-plans`，每 10 秒刷新。
- 官网公开社区日历读取 `/v1/public/activities` 的严格脱敏投影，安全快照最多缓存 30 秒；
  页面只展示企划时间与公开状态，不接收整合包 ID、清单、下载地址或签名 URL。需要活动
  客户端时只引导玩家获取并打开赫朝启动器。
- 两个后台入口都使用修订号做乐观并发控制。另一后台已保存时，旧修订提交返回冲突并要求刷新。
- 官网写入后立即失效公开活动短缓存；正常跨后台刷新仍以 Launcher API 返回值为准。
- 官网 BFF 不转发 Cookie、`Authorization`、论坛桥接令牌或签名下载地址。

## 4. 桥接配置

先在 Launcher PostgreSQL 中选择一个仍有效的 `Administrator` 用户 UUID，作为官网操作
写入 Launcher 审计日志时的服务身份。UUID 不是密码，但必须对应真实、可追责的管理员。

在服务器上的当前源码或受控脚本目录执行：

```bash
sudo bash deploy/linux/configure-website-activity-bridge.sh <actor-user-id>
```

脚本会在本机生成独立随机令牌，并原子更新两个权限 `0600` 的环境文件：

- `/home/ecs-user/hechao/.env` 保存 `HECHAO_ACTIVITY_BRIDGE_TOKEN` 明文，供 Next.js
  服务端读取；
- `/etc/hechao-launcher-api/environment` 只保存
  `WebsiteActivityBridge__InternalTokenSha256` 和 `WebsiteActivityBridge__ActorUserId`。

脚本不输出令牌或摘要，不重启 API、网站或游戏服。三枚网站服务令牌必须彼此独立；
不得复用论坛账号桥接、会话撤销或 `SESSION_SECRET`。

## 5. 发布顺序

1. 备份 Launcher PostgreSQL、API 环境和当前 API release。
2. 发布 ServerControlAgent `0.5.0` 到 owl5，只重启代理并验证活动槽心跳中的部署身份；
   不启动或停止 Minecraft。
3. 发布 Launcher API `0.30.0`，应用迁移 `028`，验证 `healthz`、`readyz`、迁移和后台。
4. 执行桥接配置脚本，再按受控顺序重启 Launcher API 与网站，使两端读取新配置。
5. 在 Launcher 后台完成一次草稿创建、相邻排期发布与重叠发布拒绝测试，随后清理测试数据。
6. 发布官网候选并验证 `/admin/activity-plans`、公开社区日历和 Launcher 活动页读取同一企划。

上述顺序已用于 2026-08-10 首次生产发布。临时数据库中的重叠发布返回
`409 schedule_conflict`，首尾相接发布成功；测试数据与候选服务已清理，生产未留下
测试企划。正式证据见 [`API_RELEASE_0.30.0.md`](API_RELEASE_0.30.0.md) 和
[`SERVER_CONTROL_AGENT_RELEASE_0.5.0.md`](SERVER_CONTROL_AGENT_RELEASE_0.5.0.md)。

迁移 `028` 是加法迁移，但旧 API 不认识企划行及部署身份。生产产生企划后，不得把 API
直接回滚到 `0.29.0` 并继续写服务器目录；应回滚到包含迁移 `028` 合同的兼容构建。

## 6. 故障处理

- 启动器能看到活动、后台月历却没有正式企划：先查看页面顶部“目录排期未纳入企划”。
  这类旧记录只有服务器目录的 `opens_at/closes_at`，没有完整企划身份。后台会以蓝色
  虚线只读显示并列出缺少的结束时间、整合包绑定或企划状态，不会自动发布、部署或
  启停 Minecraft。管理员应先完成整合包导入，补齐明确结束时间，再创建并审核正式
  企划；不要直接在数据库中强行填写 `Published`。
- `schedule_conflict`：调整草稿时间，或先撤回/归档占用区间的企划；不要删除数据库行。
- “整合包尚未进入 Production”：先完成测试并推进精确清单，不要绕过发布门禁。
- “活动槽未匹配”：停止活动服后重新部署当前企划的绑定整合包，等待代理心跳确认身份。
- “代理离线”或“操作执行中”：先恢复服控代理或等待当前结构化命令结束，不重复排队。
- 官网同步失败但 Launcher 后台正常：检查回环 URL、双端令牌摘要和两个服务是否读取了
  新环境；不要把内部端点代理到公网。
- 已到开放时间仍不能进入：依次核对企划为 `Published`、当前时间、Production 清单、
  活动槽在线、心跳新鲜、部署 import 完全一致、玩家最低称号和一次性启动授权。

## 7. 验收清单

- 创建两条重叠草稿成功；发布第一条成功，发布第二条返回 `409`。
- 第一条结束时间等于第二条开始时间时，两条均可发布。
- 拖动和两端 resize 后，两个后台在下一轮刷新显示同一时间与修订号。
- 官网能看到企划时间但没有活动客户端下载入口；玩家在 Launcher 内能提前下载
  Production 客户端，但目录为关闭且 Velocity 拒绝进入。
- 活动槽部署错误整合包、代理离线或服务端停止时均不能进入。
- 到开放时间后，仅在服务端在线且部署身份完全匹配时开放；结束时刻立即关闭。
- 官网响应、浏览器网络记录、日志和文档中没有桥接令牌、摘要、Cookie 或签名 URL。
- 部署、发布、撤回、归档、恢复和两个后台的操作均能在 Launcher 审计中追溯。
