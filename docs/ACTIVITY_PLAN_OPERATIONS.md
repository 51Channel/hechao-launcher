# 活动企划日历与真实承载槽运维手册

> 当前候选：Launcher API `0.38.4`；当前生产：Launcher API `0.38.3`
>
> `0.38.3` 新增“先创建企划、后绑定客户端”；`0.38.4` 进一步把逻辑企划与真实承载
> 服务器分离。未绑定草稿保存在独立表中；绑定客户端后才迁入正式目录。企划可以选择固定
> `activity` 或已就绪的独立槽，但发布、部署和进服始终以所选真实槽为准。任何生产
> 操作前仍要重新核对代理、承载服务器和当前玩家状态。

本功能把整合包、活动排期、玩家下载、活动槽部署和进服准入收敛到一条链路。Launcher
后台和官网后台只是两个管理入口，企划数据只保存在 Launcher PostgreSQL，不在网站
SQLite 中复制。

## 1. 唯一规则

- 可以提前建立多条草稿，也可以提前发布多条未来企划。
- 新企划可以不选择客户端整合包，先保存为 `Draft`。未绑定客户端时只允许编辑、归档和
  恢复，不能发布或部署；绑定后不能再解除绑定，但可以按既有规则改绑其他有效整合包。
- 未绑定草稿位于 `launcher.unbound_activity_plans`，不会出现在玩家启动器目录、Velocity
  准入或普通服务器目录。绑定时 API 在同一事务内保留企划 ID、创建时间并递增修订号，
  再迁入 `launcher.servers`。
- 草稿可以暂不选择客户端和承载服务器。绑定客户端时必须同时得到一个有效承载服务器；
  新后台可显式选择，旧后台未提交新字段时按“已有绑定 -> 整合包默认目标 -> 固定
  `activity`”解析，避免保存旧表单时把已经调整的承载槽改回去。
- 可以同时保留多条 `Published` 企划。同一真实承载服务器上的开放区间不能重叠；不同
  独立槽上的企划可以在同一时间发布和开放。草稿可以重叠，但同槽重叠草稿不能发布。
- 排期使用半开区间 `[开始, 结束)`。上一场在 `20:00` 结束时，下一场可以从
  `20:00` 开始，不算冲突。
- PostgreSQL 使用 `btree_gist` 和“承载服务器 ID + 半开时间区间”的复合 GiST 排斥约束
  作为最终门禁；API 在发布和移动已发布企划时先返回可读的 `409 schedule_conflict`。
  并发请求即使越过预检查，数据库仍会拒绝同槽重叠。
- 企划记录是日历、客户端和权限的逻辑记录，不是服控目标。普通后台服务器目录只显示
  真实承载服务器；逻辑企划只出现在“活动企划”。
- 已发布企划占用某个真实槽时，玩家目录只显示企划卡并隐藏该真实槽的重复卡片；撤回或
  归档最后一条占用企划后，真实槽按自身目录可见性重新出现。
- 企划的运行状态、在线人数、部署身份和 Velocity 回环端口都从真实承载槽读取。玩家不能
  通过真实槽 ID 绕过已发布企划的时间、客户端和权限门禁。
- 固定 `activity / 25568 / owl5-activity-slot` 仍只适合共享旧替换入口；独立槽使用自身
  `serverId`、`velocityTarget` 和 `25600-25611` 独立端口，可以并行承载不同企划。

## 2. 完整工作流

1. 在任一后台的“活动企划”月历点击日期或框选日期范围，先填写企划名称、公告、时间、
   人数和最低称号。客户端尚未准备好时选择“稍后绑定客户端”并创建草稿。
2. 在 Launcher 后台“整合包导入”上传 ZIP 或 MRPACK，完成自动识别与人工复核。
3. 默认选择“仅发布并入库”。客户端进入 `Test`，服务端制品保留在 API 受限存储中，
   不覆盖活动槽，也不启动 Minecraft。
4. 回到“活动企划”，为草稿绑定刚完成的整合包，并选择负责运行它的真实承载服务器。
   选择整合包时后台会带出导入时的默认目标，管理员可以改为其他已就绪槽。已绑定企划
   不能改回“稍后绑定”；保存成功后企划 ID 和创建时间保持不变，修订号递增。
5. 完成客户端和服务端测试后，在客户端档案后台把该精确清单推进到 `Production`。
   未进入 `Production`、已暂停或档案已归档的整合包不能发布企划。
6. 调整开放与结束时间。拖动改变整个区间，拖动两端改变开始或结束；草稿重叠只警告。
7. 发布企划。API 会再次验证承载服务器存在且可部署，并检查同一承载槽没有重叠排期。
   发布后同一数据会出现在 Launcher 活动页、官网社区日历和 ICS。官网只
   展示企划时间与公开信息；玩家必须进入 Launcher 活动页下载或更新绑定客户端。开放前
   目录状态保持 `Closed`，不能取得有效进服授权。
8. 所选承载服务器停服且代理在线时，使用精确确认 `DEPLOY <planId>` 部署企划整合包。
   部署命令只进入该真实槽的命令队列；完成后仍保持停服，心跳会上报实际部署的 import、
   档案和版本身份。
9. 在开放窗口前由管理员按现有服控流程启动真实承载服务器。只有当前时间进入排期、
   服务端在线、代理心跳新鲜且该槽部署身份与企划绑定整合包完全一致时，目录与 Velocity
   才允许进入。
10. 活动结束时目录自动关闭准入；Minecraft 进程不会被日历自动停止，管理员仍按服控
   流程安全停服。需要改期时先保证新的已发布区间不与其他企划重叠。

“立即部署所选槽”只用于兼容旧导入流程。新企划应优先使用“仅发布并入库”，随后从
企划日历选择整合包和真实承载服务器，再执行受控部署。

## 3. 四个入口如何同步

- Launcher 活动页读取同一 API 目录；打开页面时立即刷新，停留期间每 30 秒刷新，离开
  页面后停止轮询。客户端下载、更新和本地安装状态只存在于 Launcher。
- Launcher 后台直接调用 `/v1/admin/activity-plans`，每 5 秒刷新。
- 官网后台 `/admin/activity-plans` 只调用同站 `/api/admin/activity-plans`；Next.js
  BFF 再从回环地址调用 `/v1/internal/website/activity-plans`，每 10 秒刷新。
- 官网公开社区日历读取 `/v1/public/activities` 的严格脱敏投影，安全快照最多缓存 30 秒；
  页面只展示企划时间与公开状态，不接收整合包 ID、清单、下载地址或签名 URL。需要活动
  客户端时只引导玩家获取并打开赫朝启动器。
- 两个后台入口都使用修订号做乐观并发控制。另一后台已保存时，旧修订提交返回冲突并要求刷新。
- 两个后台都必须保留 `targetServerId`。旧后台未提交该字段时 API 保留已有绑定，不能在
  普通保存、拖动或调整时间时静默改回整合包默认槽。
- 官网写入后立即失效公开活动短缓存；正常跨后台刷新仍以 Launcher API 返回值为准。
- 官网 BFF 不转发 Cookie、`Authorization`、论坛桥接令牌或签名下载地址。

## 4. 桥接配置

先在 Launcher PostgreSQL 中选择一个仍有效的 `Administrator` 用户 UUID，作为官网操作
写入 Launcher 审计日志时的服务身份。UUID 不是密码，但必须对应真实、可追责的管理员。

在服务器上的当前源码或受控脚本目录执行：

```bash
sudo bash deploy/linux/configure-website-activity-bridge.sh <actor-user-id>
```

脚本会在本机生成独立随机令牌，并原子更新两个权限 `0600` 的环境文件：

- `/home/ecs-user/hechao/.env` 保存 `HECHAO_ACTIVITY_BRIDGE_TOKEN` 明文，供 Next.js
  服务端读取；
- `/etc/hechao-launcher-api/environment` 只保存
  `WebsiteActivityBridge__InternalTokenSha256` 和 `WebsiteActivityBridge__ActorUserId`。

脚本不输出令牌或摘要，不重启 API、网站或游戏服。三枚网站服务令牌必须彼此独立；
不得复用论坛账号桥接、会话撤销或 `SESSION_SECRET`。

## 5. 发布顺序

API `0.38.4` 的生产升级顺序：

1. 备份 Launcher PostgreSQL、API 环境、systemd 单元和当前不可变 release。
2. 原子发布 API，只重启 `hechao-launcher-api.service`。迁移 `037` 安装可信扩展
   `btree_gist`，只从合法固定 `activity` 或已就绪独立槽中为既有企划回填真实承载槽，
   并把排期约束改为按槽隔离；`survival2` 等普通固定服不会成为回填候选。
3. 验证迁移 `37/37`、扩展存在、普通后台不含逻辑企划、活动企划显示真实绑定、玩家目录
   不重复，以及 Velocity 返回真实槽 ID 和回环端口。
4. 确认 Minecraft、Velocity、Publisher 和服控代理 PID 未变化；本升级不操作这些进程。

以下为 `0.30.0` 首次引入活动企划时使用的历史顺序：

1. 备份 Launcher PostgreSQL、API 环境和当前 API release。
2. 发布 ServerControlAgent `0.5.0` 到 owl5，只重启代理并验证活动槽心跳中的部署身份；
   不启动或停止 Minecraft。
3. 发布 Launcher API `0.30.0`，应用迁移 `028`，验证 `healthz`、`readyz`、迁移和后台。
4. 执行桥接配置脚本，再按受控顺序重启 Launcher API 与网站，使两端读取新配置。
5. 在 Launcher 后台完成一次草稿创建、相邻排期发布与重叠发布拒绝测试，随后清理测试数据。
6. 发布官网候选并验证 `/admin/activity-plans`、公开社区日历和 Launcher 活动页读取同一企划。

上述顺序已用于 2026-08-10 首次生产发布。临时数据库中的重叠发布返回
`409 schedule_conflict`，首尾相接发布成功；测试数据与候选服务已清理，生产未留下
测试企划。正式证据见 [`API_RELEASE_0.30.0.md`](API_RELEASE_0.30.0.md) 和
[`SERVER_CONTROL_AGENT_RELEASE_0.5.0.md`](SERVER_CONTROL_AGENT_RELEASE_0.5.0.md)。

迁移 `037` 是加法迁移，旧 API `0.38.3` 可以在紧急情况下读取迁移后的数据库，但它不
理解真实承载槽字段，会重新出现逻辑企划混入普通目录、玩家目录重复和固定槽回退语义。
因此回滚仅用于短时故障恢复，期间应冻结活动企划和服务器目录写入，并尽快恢复
`0.38.4` 或更高兼容构建。迁移本身不向下删除。

## 6. 故障处理

- 启动器能看到活动、后台月历却没有正式企划：先查看页面顶部“目录排期未纳入企划”。
  这类旧记录只有服务器目录的 `opens_at/closes_at`，没有完整企划身份。后台会以蓝色
  虚线只读显示并列出缺少的结束时间、整合包绑定或企划状态，不会自动发布、部署或
  启停 Minecraft。管理员应先完成整合包导入，补齐明确结束时间，再创建并审核正式
  企划；不要直接在数据库中强行填写 `Published`。
- `schedule_conflict`：调整草稿时间、改选另一个独立槽，或先撤回/归档占用同一承载槽
  区间的企划；不要删除数据库行。
- `package_binding_required`：企划仍未绑定客户端。先在编辑器中选择已完成整合包并保存，
  再发布或部署；不要直接修改数据库把未绑定草稿伪装成正式目录记录。
- `target_binding_required` / `target_not_found`：选择一个后台列出的已配置承载服务器。
  不要把逻辑企划 ID、基础设施目标或未完成创建的槽写入数据库。
- “整合包尚未进入 Production”：先完成测试并推进精确清单，不要绕过发布门禁。
- “部署未匹配”：停止企划绑定的真实承载服务器后重新部署当前整合包，等待该槽心跳确认身份。
- 普通服务器目录和活动企划同时出现同一活动：核对普通目录只有真实槽，逻辑企划只存在于
  活动企划；再检查 API 是否至少为 `0.38.4`，不要手工删除真实槽。
- “代理离线”或“操作执行中”：先恢复服控代理或等待当前结构化命令结束，不重复排队。
- 官网同步失败但 Launcher 后台正常：检查回环 URL、双端令牌摘要和两个服务是否读取了
  新环境；不要把内部端点代理到公网。
- 已到开放时间仍不能进入：依次核对企划为 `Published`、当前时间、Production 清单、
  真实承载服务器在线、心跳新鲜、部署 import 完全一致、玩家最低称号和一次性启动授权。

## 7. 验收清单

- 创建两条同槽重叠草稿成功；发布第一条成功，发布第二条返回 `409`。把第二条改到另一
  独立槽后可以在同一时段发布。
- 不选择客户端创建草稿成功；它能编辑、归档和恢复，但发布、部署均返回
  `409 package_binding_required`，玩家启动器目录中不存在该记录。
- 为未绑定草稿补选整合包后，企划 ID 和创建时间不变、修订号递增，并且不能再解除绑定。
- 逻辑企划不出现在普通服务器目录；普通目录仍保留真实承载槽用于服控和配置。
- 企划发布后玩家目录只显示企划卡，不显示真实槽重复卡；直接请求真实槽 ID 也不能绕过。
- 第一条结束时间等于第二条开始时间时，两条均可发布。
- 拖动和两端 resize 后，两个后台在下一轮刷新显示同一时间与修订号。
- 官网能看到企划时间但没有活动客户端下载入口；玩家在 Launcher 内能提前下载
  Production 客户端，但目录为关闭且 Velocity 拒绝进入。
- 真实承载槽部署错误整合包、代理离线或服务端停止时均不能进入。
- 到开放时间后，仅在服务端在线且部署身份完全匹配时开放；结束时刻立即关闭。
- 官网响应、浏览器网络记录、日志和文档中没有桥接令牌、摘要、Cookie 或签名 URL。
- 部署、发布、撤回、归档、恢复和两个后台的操作均能在 Launcher 审计中追溯。
