## 2. 阻断问题

### 2.1 权威经济后端未上线

经济源码只存在于远端候选分支
`origin/codex/skyrealm-one-click-economy-screen@a4e1da2`，没有合入
`origin/main@e7483ed`。候选文档本来也标注“未部署 API、未执行迁移、未注入生产令牌”，
但客户端和服务端 JAR 后来已经随工业季包进入生产。

当前实际行为：

- TAB 的 `%hechao_balance%` 返回 `--`；
- `/money` 无法取得权威余额；
- `/pay`、`/sell`、商品维护和所有写交易故障关闭；
- 不会降级到 Essentials 本地余额，也没有证据表明产生了错误账本记录。

### 2.2 旧候选不能直接部署

候选把经济迁移注册为 `029_economy_ledger.sql`。现行主线已经使用：

- `029_dynamic_deployment_slots.sql`；
- `030_independent_deployment_slots.sql`。

直接合并或发布旧候选会触发迁移版本/校验和冲突。经济模块必须从最新 `origin/main`
重新集成，把账本迁移顺延为新的加法迁移，并使用高于生产 `0.32.2` 的 API 版本；不能
直接运行旧文档中的 `0.31.1` 发布步骤。

### 2.3 TAB 占位符不会主动预热余额

`%hechao_balance%` 只调用 `cachedBalance()`，缓存为空时直接返回 `--`，不会异步查询
API。插件也没有玩家加入时的余额预热。因此，即使后端和凭据补齐，新玩家仍会先看到
`--`，直到 `/money`、交易或其他 Vault 查询碰巧填充缓存。

修复应使用主线程非阻塞的单飞异步刷新，并在玩家加入、缓存过期和占位符首次命中时
触发；同一 UUID 不得因 TAB 高频刷新产生并发请求风暴。

### 2.4 Essentials 命令所有权仍需修复

Essentials `2.21.0` 比 HechaoEconomy 更早加载，并声明 `balance/money`、`pay` 和
`sell`。当前 Essentials 配置虽然禁用了这些命令，但只检查配置文本不能证明 Bukkit
根命令已经由 HechaoEconomy 接管。屏幕当前执行未带命名空间的 `money`、`sell`，仍有
进入旧命令或空命令的风险。

屏幕动作应改为 `hechaoeconomy:<command>`，插件启动健康检查还应验证玩家可见的
`/money`、`/balance`、`/pay` 和 `/sell` 的真实 CommandMap 所有者；验证失败时继续
故障关闭并给出明确日志。

### 2.5 Vault 目前仅提供只读兼容

Vault 的 `withdrawPlayer`、`depositPlayer` 和银行接口全部返回 `NOT_IMPLEMENTED`。
这是防止第三方插件绕过审计的安全选择，但也意味着领地购买、第三方商店或任何依赖
Vault 扣款/退款的功能目前不能使用赫朝金币。后续必须为每类写入建立显式、可审计的
Economy Service 操作，不能简单开放通用增减余额。

## 3. 自定义屏幕边界

已确认的安全措施：

- 客户端只回传 `sessionId + actionId`，不发送任意命令文本；
- 服务端只接受 `balance`、`shop`、`sell`、`admin_product`、`settings`、`team`
  六个固定 action，并以玩家身份执行对应命令；
- 会话按玩家 UUID 绑定，有效期 `2` 分钟，最小动作间隔 `350 ms`；未知 action、错误
  会话和过快请求会被拒绝；
- 标题最多 `64` 字符、副标题 `160` 字符、按钮 `1-16` 个，action/标签/说明分别限制
  为 `32/32/96` 字符；
- `heco product` 最终仍由 Bukkit 权限 `hechao.economy.admin` 和物品规则裁决，普通
  玩家不能借屏幕提升权限。

仍需收紧的部分：

- 客户端接受当前连接服务器发来的 `open_menu` 文本和按钮定义，没有绑定赫朝服务器
  身份。安装同协议模组的第三方服务器可以伪装“天域远征”界面，但只能让客户端回传
  action ID，不能执行本地命令、操作系统程序或赫朝服务器命令。为避免品牌欺骗，标题、
  说明和固定动作文案应由客户端内置，服务端只下发会话和可用 action 集。
- `validateAndConsume` 并未真正消费会话；同一会话在两分钟内可按 `350 ms` 间隔重放。
  当前屏幕点击后会关闭，但改包客户端仍可重发。首个允许动作后应删除会话，需要再次
  操作时重新打开屏幕。
- `admin_product` 对所有玩家可见，虽然服务端权限会拒绝普通玩家，界面仍会给出无效
  按钮。服务端生成按钮时应按权限过滤。
- 编码允许最多 `16` 个按钮，但界面没有滚动、换行或文本裁切；当前固定 `6` 个按钮在
  常见分辨率下正常，第三方或未来扩展到上限时可能超出低高度窗口，长说明也可能横向
  溢出。
- 过期会话只在再次提交时删除，玩家离线没有清理。当前人数规模下影响很小，但应增加
  断线清理和周期清理。

## 4. 已通过的设计点

- API 基址只接受 HTTPS，HTTP 客户端禁止重定向，并同时设置连接和请求超时；
- 转账和出售提交使用幂等键，出售提交遇到不确定结果只使用同一请求重试；
- 物品在报价确认前再次检查，失败后优先退回背包，无法恢复时写入隔离记录；
- 命名、附魔、容器和带组件物品默认拒绝，普通模组物品按完整命名空间 ID 处理；
- API 不可用、令牌缺失或 Vault 所有权异常时，新交易统一暂停。

## 5. 推荐修复顺序

1. 从最新 `origin/main` 新建集成分支，迁移 Economy API、模型和测试；将账本迁移顺延为
   新版本，先做隔离 PostgreSQL 迁移、并发、幂等和恢复演练。
2. 发布高于 `0.32.2` 的 API 候选，先验证无凭据为 `401/403`、错误服务 ID 被拒绝、
   正确凭据才能读取空账户；不得在证据中记录令牌或签名地址。
3. 发布 HechaoEconomy `0.1.3`：修复占位符异步预热与单飞、命令所有权自检、配置对象
   的令牌脱敏，并明确 Vault 只读兼容状态。
4. 发布 Screen `0.1.3`：使用命名空间命令、按权限生成按钮、一次性会话、客户端固定
   文案和可滚动/裁切布局。
5. 在停服备份、API 与数据库恢复点都完成后外置创建服务凭据。令牌文件可用
   `/heco reload` 热加载；新增环境变量不能注入已运行 JVM，使用环境变量时必须在维护
   窗口重启后端。
6. Test 通道完成余额、转账、报价、补偿、商品维护、TAB、第三方 Vault 拒绝和真人
   进服验收后，再按 `2/3/5/20` 人灰度。Gray/Production 在此之前保持不变。
