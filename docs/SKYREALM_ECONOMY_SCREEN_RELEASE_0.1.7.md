`0.1.7` 不再只显示“正在……”后把结果放回聊天栏，而是让三项高频动作直接打开业务 UI：

- 余额页在游戏内持续显示加载、成功或错误结果；
- 出售页先显示服务端报价，收到有效报价后才出现“确认出售”；
- 回收目录把旧箱子视图替换为响应式商品网格，支持图标、价格、悬浮提示、空状态、分页
  和滚轮翻页；
- 结果页在 `200 tick` 无响应时给出超时错误，并限制最多六条结果；
- 服主设置、个人设置和队伍保持原行为。

客户端只展示服务端已经裁决的数据。权限、短期会话、固定动作、报价、出售确认与商品目录
仍由服务端负责；网络协议保持 `2`，生产服务端 Screen `0.1.3` 继续兼容。当前生产商品
表仍为 `0` 条，文档中的 `85` 项待审核候选没有导入生产库。

Gradle `clean test build` 与 `22/22` 测试通过，清理后重建的 JAR 大小和 SHA-256 与
已上传制品一致。客户端档案 `1.0.16` 已发布到 `Test=r9 / 100%`；Gray 与 Production
保持未分配。没有重启 API、Minecraft、Velocity 或服控代理。

玩家必须完全退出旧游戏，再由启动器增量更新后验收余额、出售报价与确认、目录空状态和
后续正式商品分页。完成真人验证前不得推进 Gray 或 Production。
