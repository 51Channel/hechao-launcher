# API 0.29.0 发布候选

> 状态：`DEPLOYED`
> 当前生产：API `0.29.0-20260808T043921Z`，数据库迁移 `027`
> 正式记录：[`API_RELEASE_0.29.0.md`](API_RELEASE_0.29.0.md)

## 功能范围

- 新增迁移 `027_client_profile_lifecycle`，在客户端档案上记录归档时间、操作者与原因；
- 新增档案归档、恢复和受限永久删除端点，全部要求管理员 MFA、CSRF、当前修订号与审计；
- 归档前要求零服务器引用；归档保留不可变版本、三个通道、签名清单和 OSS 对象；
- 恢复固定回到停用状态，不自动向玩家分发；
- 永久删除只允许已归档、零版本、零服务器引用的空草稿，并要求原因和精确确认文本
  `DELETE <profileId>`；
- 已归档档案的元数据、版本导入、通道修改、回滚和版本暂停全部由 API 拒绝；
- Publisher 遇到归档目标时以不可重试的 `PROFILE_ARCHIVED` 结束，不写入新的签名清单；
- 已完成客户端发布但尚未最终化的整合包会锁定并复核档案状态，归档目标不会重新写入
  服务器目录、Test 通道或启用状态；
- Vue 后台增加“使用中 / 已归档 / 全部”筛选，明确区分启用、停用、草稿和已归档，
  并在抽屉中展示服务器引用、不可变版本数量及不能删除的原因。

## 发布边界

本候选带数据库迁移，不能按普通静态页面修复直接上线。生产部署前必须先完成 PostgreSQL
custom-format 备份及 `pg_restore --list`，再发布 API；只允许重启
`hechao-launcher-api.service`，不得操作 Publisher、Nginx、Minecraft、Velocity 或两台
ServerControlAgent。

迁移 `027` 只增加列、检查约束和索引，不删除数据。应用迁移但尚未执行任何档案归档时，
可将 API 二进制回滚到 `0.28.7`；一旦存在已归档档案，旧 API 不理解归档状态，禁止再用
旧后台修改这些档案。此时应优先前滚修复 `0.29.x`，不得删除迁移、发布记录或审计数据。

正式部署中的首次制品因 `DELETE` 请求体未显式标注 `[FromBody]` 而被 ASP.NET 10 在
启动阶段拒绝，就绪门禁自动回滚。修复提交 `43da4ae` 已补充端点绑定回归测试，并在独立
数据库和备用端口真实启动后以前滚制品完成上线。详情见正式发布记录和结构化证据。
