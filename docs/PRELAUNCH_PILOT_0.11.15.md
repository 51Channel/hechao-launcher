# 启动器 0.11.15 小范围测试手册

> 范围：管理员本机与 2 至 3 名内部玩家
>
> 目标：验证日志配置修复，并回归登录、安装、修复、回滚、诊断上传与真实游戏启动

## 当前前置门槛

2026-07-28 的生产只读审计显示，目前只有 1 个社区账号绑定 Minecraft，尚不满足
2 至 3 人真实灰度条件。开始多人手册前必须先完成：

- 准备至少 2 至 3 个真实 Microsoft/Minecraft 正版账号并完成赫朝绑定；
- 确认目标服务已由管理员开启，目录状态与真实运行状态一致；
- PVP 后端确认 CrossStitch `0.1.6` 与 FabricProxy-Lite `2.6.0` 同时加载，并完成
  修复后的真实进服复测；
- 从启动器创建新的管理员后台票据，完成 MFA 后打开运行数据、服务状态与告警页面；
- 保留当前安装包和上一稳定版本的回滚来源、大小及 SHA-256。

完整门槛快照见
[`PRODUCTION_ACCEPTANCE_GATES_2026-07-28.md`](PRODUCTION_ACCEPTANCE_GATES_2026-07-28.md)。

## 安装前

- 只使用管理员提供的私有短时链接。
- 文件名必须为 `Hechao-Launcher-Setup-0.11.15-win-x64.exe`。
- 文件大小必须为 `61,867,426` 字节。
- SHA-256 必须为
  `3C9139F8F7853C370C83A14537916D73258123A8E1CB26FDBA0B0EECD3219E44`。
- 可以直接覆盖 `0.11.14`，不要删除客户端、Java 或游戏数据目录。
- 安装包未做 Authenticode 签名；只接受上述文件名、大小和 SHA-256。

## 必测流程

1. 覆盖安装后确认版本显示 `0.11.15`，赫朝账号、Minecraft 绑定、设置、
   已安装档案、受管 Java 与玩家存档保留。
2. 对基础、Activity 和 PVP 档案各执行一次启动准备；确认缺失的
   `assets/log_configs/*.xml` 会自动下载，启动器保持响应。
3. 删除一个非运行中档案的日志配置后再次启动，确认文件按元数据长度和哈希恢复，
   同目录没有 `.tmp` 遗留。
4. 分别完成 Lobby、Survival、Activity 和 PVP 的代理路由；核对服务端 UUID、
   等级、NPC、`/hub`、断线重连和正常退出。
5. 登录失败、取消登录、选错 Microsoft 账号、网络中断和游戏异常退出时，启动器
   必须保持运行并显示可重试状态。
6. 分别回归一次安装或修复、一次主动回滚和一次真实游戏启动；中断下载后继续，
   确认从已有分片续传。
7. 以自动 Java 启动 Java 21 与 Java 17 档案各一次，再为单个档案选择自定义 Java，
   确认互不串用。
8. 生成脱敏诊断包并主动确认上传；取消、网络失败和文件被修改时都不得退出启动器。
9. 管理员登记 MFA 后核对运行数据中的版本、事件结果和失败分类，并下载诊断编号、
   核对下载审计。

## 通过条件

- Mojang 日志配置缺失或损坏时可自动恢复；非法元数据不会写出受管目录。
- 登录失败、取消登录、检查失败、安装失败和上传失败均不会退出启动器。
- 全新安装与 `0.11.14` 覆盖升级不清除账号、设置、客户端或玩家数据。
- Activity 与 PVP 的正确档案、身份转发、返回大厅和重连均有真实日志证据。
- 自动 Java、修复、回滚和真实启动至少各完成一次。
- 本轮无阻断问题后才能进入 5 人灰度；5 人通过后再进入 20 人灰度。
