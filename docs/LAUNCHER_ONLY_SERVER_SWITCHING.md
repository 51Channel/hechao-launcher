# 启动器唯一切服与基础设施大厅隔离决策

> 决策日期：2026-07-29
>
> 状态：生产部署与自动验收完成，待真实四级账号和多人灰度
>
> 适用范围：赫朝启动器、启动器 API、Velocity、owl5 游戏服、owl9 恐怖整蛊服、
> 状态采集、等级同步、备份与运维文档

## 1. 最终决定

大厅不再是玩家入口、可玩服务器、回退服或转服中转站。玩家选择服务器和更换服务器
只能通过赫朝启动器完成。

大厅服务端本身保留并继续常驻，作为 LuckPerms 等前置能力的内部承载器。保留大厅进程
不等于允许玩家进入：大厅必须同时从玩家目录、进服授权、Velocity 首次路由、默认回退、
游戏内命令和 NPC 转服中隔离。

Velocity 继续作为唯一公网 Minecraft 入口，负责隐藏后端地址、modern forwarding、
一次性启动授权和服务端二次权限校验。客户端仍不允许绕过 Velocity 直连任何玩家服。

生产中的历史 server ID `lobby` 按“内部基础设施目标”处理：

- 不出现在玩家在线目录、缓存目录或内置应急目录。
- 不签发玩家进服授权，也不能作为首次目标、回退目标或转服目标。
- `lobby` 可以仅作为 Velocity 触发首次改写所需的内部引导占位；它不是可授权目的地，也
  不能在改写失败、目标断开或 API 故障时成为回退服。
- `/hub`、`/lobby`、`/l`、NPC 转服和其他游戏内跨服入口全部停用。
- `allow_protocol_translation` 保持 `false`，不为返回大厅启用 ViaVersion 或
  ViaBackwards。
- 大厅计划任务、服务端目录、端口 `25566`、等级代理、指标采集和备份继续保留，但监听
  与防火墙只能满足本机或明确的内部运维需要，不能形成玩家连接路径。

数据库中的历史大厅记录、审计、授权历史、指标样本和世界备份不物理删除。玩家目录记录
设置为 `is_visible=false`、`allow_protocol_translation=false`，授权端必须显式拒绝。
平台需要把“玩家可见/可授权”和“内部监控”拆成两个维度，使大厅在管理员基础设施视图、
告警和备份中保持启用，但不能重新进入玩家目录。

## 2. 玩家切服规则

赫朝启动器是唯一切服控制器，必须满足以下行为：

1. 点击目标服务器前，重新检查账号、权限、服务器状态、客户端档案和本地文件。
2. 没有 Minecraft 进程时，申请该目标的一次性授权并直接启动对应档案。
3. 已有 Minecraft 进程时，主操作显示“切换服务器”或“重新连接”，先请求当前游戏
   正常退出；超时后才允许结束进程，并且必须向玩家显示状态。
4. 当前游戏完全退出后，才可申请新目标授权和启动新档案。任意时刻只允许一个由启动器
   管理的 Minecraft 进程。
5. 同版本、跨版本以及 Paper、Fabric、NeoForge 等不同加载器都走同一流程；不同档案
   自动使用各自的 `.minecraft` 和受管 Java。
6. 切换失败时保留原档案、存档、设置和客户端版本；不得留下半启动的新进程或消费后
   无法重试的错误授权。
7. 服务器维护、崩溃或拒绝连接时不自动把玩家送往大厅或其他游戏服。启动器恢复可操作
   状态，显示可理解原因，由玩家重新选择目标。

启动器可以继续使用“服务器”工作区，但玩家可见名称应为“服务器列表”，避免把启动器
界面误认为游戏内大厅。

## 3. 服务端和平台约束

### 3.1 Velocity

- 保留 `mc.hehe11.fun` 统一入口和现有 forwarding secret。
- 保留 Authorizer，并以启动器的一次性授权决定首次目标。
- `lobby` 若继续注册，只能作为首次连接的内部引导占位。有效授权必须在进入后端前改写
  到目标服；授权缺失、无效、已消费、API 不可用或目标不可用时必须硬拒绝，即使其余
  权限仍处于 `monitor`。
- 关闭目标异常断开后的自动 failover，删除 HubCommand 和所有把玩家送回大厅的路径。
- 删除或禁用代理上只为大厅回程部署的 ViaVersion/ViaBackwards；客户端档案必须与
  目标服版本匹配。
- 没有有效目标授权时直接拒绝连接，不回退到大厅或任意游戏服。
- 大厅后端增加独立的“拒绝全部玩家登录”保护，例如空白名单或专用登录守卫；即使
  Authorizer 未加载或异常，也不能让玩家完成大厅登录。

### 3.2 API 和目录

- 隐藏 `lobby` 玩家目录记录，并拒绝针对不可见目标的新授权。
- 在线目录、缓存和内置应急目录都不得向玩家返回大厅。
- 数据模型增加等价于 `is_player_target=false`、`monitoring_enabled=true` 的角色表达；
  不能用一个 `is_visible` 同时控制玩家目录和内部告警。
- 管理后台把大厅标记为“内部基础设施”，允许查看运行状态、指标和审计，但不能通过普通
  目录编辑把它重新开放给玩家。
- 目录强制登录与 Velocity `enforce` 仍按独立灰度门槛推进。

### 3.3 玩家游戏服

- 后端继续只接受 Velocity modern forwarding。
- 移除或停用所有把玩家送往 `lobby` 的命令、NPC 和插件配置。
- 不用另一个生存服或活动服冒充默认大厅。
- owl9 的历史目标 `pvp` 仍只代表 `C:\mc\server` 的恐怖整蛊服，不能触碰
  `E:\MinecraftServer` 的真正 PVP 服。

### 3.4 基础设施大厅

- `E:\LobbyServer` 和 `Hechao-Server-Lobby` 任务继续运行，不迁移现有
  `Hechao.LuckPermsTierAgent`，除非后续另行批准架构变更。
- 等级代理必须继续完成四级主组读取、写入、幂等重试和队列恢复验收。
- 状态采集、TPS/MSPT/GC、运行告警和备份继续保留，但大厅计入“内部基础设施”，不计入
  玩家可选服务器数量、玩家在线目标或开放率。
- 大厅世界和配置继续纳入备份及恢复检查；不得因为玩家不可进入而失去回滚能力。
- 停用 NPC、传送命令、玩家公告和其他纯玩家功能，减少不必要插件冲突面。
- 大厅后端的拒绝玩家保护必须独立于 Velocity Authorizer，并在 Authorizer/API
  故障演练中保持生效。
- 公网和其他非授权来源不能直连 `25566`；日常维护使用计划任务、控制台和内部运维通道。
- 大厅故障只影响其承载的前置能力并触发内部告警，不能导致玩家被自动转入其他游戏服。

## 4. 自动回滚要求

生产改动使用一个时间戳变更集，至少备份：

- Velocity 配置、插件、任务 XML 和最近日志。
- 大厅配置、插件清单、任务 XML、最近日志和世界正式备份引用。
- 状态采集器、等级代理、告警与备份配置。
- PostgreSQL 一致性备份及 `lobby` 行的变更前快照。

执行顺序为“备份 -> 发布 API/启动器 -> 隐藏大厅并拒绝授权 -> 修改 Velocity ->
停用游戏内转服 -> 收紧大厅网络边界 -> 验收”。任一步失败时按相反顺序恢复，且回滚后
必须重新核对监听、玩家目录、授权、等级代理、指标、备份和公开入口。回滚不得把大厅
恢复为默认玩家入口；若必须临时开放，只能作为单独的应急变更审批和记录。

## 5. 完成标准

以下条件全部满足后，才可以把本决策标记为已完成：

- 启动器玩家在线目录、缓存和内置应急目录均无 `lobby`。
- 启动器可在同档案和不同档案之间完成至少三轮切换，每轮只存在一个 Minecraft 进程，
  每次使用新的目标授权。
- Survival1、Survival2、Activity、恐怖整蛊和后续正式接入的服务器均可从启动器直达；
  关闭或维护目标仍被正确拒绝。
- `lobby` 不可获得玩家授权；Velocity 即使保留引导占位也不能让玩家落入大厅，并且无
  自动回退、无 HubCommand、无大厅回程 Via 翻译层。
- 普通玩家从公网、Velocity、命令、NPC 和直接后端地址均不能进入大厅。
- Authorizer 未加载、API 超时、授权缺失/重复消费和目标服异常断开时，玩家仍不能进入
  大厅或其他未授权服务器。
- 大厅任务和内部监听保持健康，LuckPerms 等级代理完成真实读取、写入、失败重试与恢复
  验收。
- 大厅指标、告警和备份继续工作，并在管理后台明确显示为内部基础设施而非玩家服务器。
- 各玩家后端没有可用的 `/hub`、NPC 或其他游戏内转服路径。
- 普通、Participant、Collaborator、Administrator 四级真实账号完成目录与进服灰度。
- 自动测试、安装包、API 发布、生产健康检查、旧网站和中转 API 回归通过，代码与证据
  已提交并推送。
