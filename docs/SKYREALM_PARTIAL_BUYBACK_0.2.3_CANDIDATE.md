## 根因

旧 API 在创建报价时使用整组判断：请求数量只要超过个人或全服剩余额度，就直接返回
`409`。因此苹果个人上限为 `32`、当天用量为 `0` 时，玩家放入 `64` 个苹果仍会整组失败。
旧插件又把所有 `409` 显示成“额度不足或回收已暂停”，无法区分真实原因。

## 修复合同

API 使用以下权威数量创建报价：

```text
min(请求数量, 个人上限 - 个人已用, 全服上限 - 全服已用)
```

可回收数量大于 `0` 时，报价数量、总金额和两类剩余额度都按裁剪后的数量计算；等于 `0`
时继续返回 `PERSONAL_LIMIT_EXCEEDED` 或 `SERVER_LIMIT_EXCEEDED`。商品不存在和商品暂停语义
保持不变。

插件用原始槽位快照做防篡改校验，只把 API `quote.quantity` 对应数量放入托管。未报价余量
留在输入槽；成功时明确显示本次回收和保留数量，明确失败时合并恢复原整组，结果未知时只
隔离报价数量。API 返回的结构化错误码会分别显示商品暂停、个人额度已用完和全服额度已用完。

## 兼容与部署

API `0.36.1` 的部分报价与插件 `0.2.2` 不兼容，因为旧插件要求当前槽位数量必须等于报价
数量。生产必须在同一维护窗口切换 API `0.36.1` 和 HechaoEconomy `0.2.3`；任一步失败都
恢复 API `0.36.0` 与插件 `0.2.2`。本版不改变数据库结构、客户端协议、Screen 或客户端
档案，不上传 OSS，也不切换 Test、Gray、Production 指针。
