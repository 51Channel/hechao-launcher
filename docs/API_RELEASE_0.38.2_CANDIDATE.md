> 候选日期：`2026-09-04`
> 状态更新（2026-09-04）：本候选已完成生产备份、原子部署和真实浏览器验收。正式
> 记录见 [`API_RELEASE_0.38.2.md`](API_RELEASE_0.38.2.md)；本文件保留候选阶段证据，
> 不代表当前实时状态。

## 问题与根因

商业街服务器已经存在于 `launcher.servers` 和服控目标中，但它按独立槽发布边界保持
`isVisible=false`。服务器目录页面默认只列出 `isVisible=true` 的记录，并把隐藏记录
错误命名为“已归档”；新增服务器抽屉又会正确排除已经建档的 ID，于是管理员同时看到
“目录里没有商业街”和“0 个可添加”。数据没有丢失，问题仅在后台筛选默认值和文案。

## 修复范围

- 服务器目录默认显示全部已建档记录，玩家隐藏的商业街仍可由管理员查看和管理；
- 筛选改为“全部 / 玩家可见 / 玩家隐藏”，汇总与状态文案同步纠正；
- 行操作改为“对玩家隐藏 / 向玩家展示”，明确它不会启停 Java 进程；
- 已建档的隐藏服务器继续从自动发现列表排除，避免重复创建目录记录；
- 本修复不主动修改商业街生产数据；玩家展示和入口策略仍由管理员单独决定。

## 部署与回滚

发布前备份 PostgreSQL、API 环境文件、systemd 单元和当前发布链接。使用
`deploy/linux/install-release.sh` 原子切换，只重启 `hechao-launcher-api.service`；
就绪检查失败时自动切回 `0.38.1-20260904T002600Z`。本版不新增数据库迁移，不操作
Publisher、Nginx、Velocity 或任何 Minecraft 服务端。
