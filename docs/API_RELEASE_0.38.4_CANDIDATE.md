# 赫朝启动器 API 0.38.4 活动企划真实承载槽候选

> 候选日期：`2026-09-04`
> 状态：实现和发布前完整验证已完成，尚未部署生产

## 目标

修复活动被同时当作“企划”和“真实服务器”展示的问题，并允许管理员先创建企划，之后
再绑定客户端整合包和负责运行它的真实承载服务器。

以商业街为例：逻辑企划 `activity-20260905-69e6741d9` 只出现在“活动企划”和玩家活动
目录；真实槽 `minigame-commercial-street / 25602` 只出现在普通服务器目录和服控面板。
部署、运行状态、在线人数和 Velocity 动态回环全部使用真实槽。

## 行为边界

- 新企划允许选择“稍后绑定客户端”和“稍后选择承载服务器”，保存为未绑定 `Draft`；
- 未绑定企划允许编辑、归档和恢复，不允许发布或部署；API 分别返回明确的
  `409 package_binding_required` 或 `409 target_binding_required`；
- 绑定已完成且未归档的整合包后，在同一事务内保留企划 ID、创建时间并递增修订号；
- 新后台可显式选择固定 `activity` 或已就绪的独立槽。旧后台不提交 `targetServerId` 时，
  按“已有绑定 -> 整合包默认目标 -> 固定 activity”解析，普通保存不会把已调整目标改回；
- 只有绑定客户端、绑定有效承载服务器且精确清单进入 `Production` 的企划可以发布；
- 同一承载服务器上的已发布企划使用 `[开始, 结束)` 排斥，不同独立槽允许同一时段发布；
- 普通后台服务器目录排除逻辑企划，但仍显示并管理真实承载槽；
- 玩家目录在企划发布时只显示企划卡，隐藏对应真实槽的重复卡片；
- 被企划占用而隐藏的真实槽不能再单独开放旧客户端档案下载；玩家权限预览也使用企划
  绑定槽的运行状态和部署身份，不再把逻辑企划误判为离线；
- Velocity 不能通过真实槽 ID 绕过已发布企划，授权响应使用企划绑定槽的真实
  `velocityTarget` 和动态回环端口；
- 活动部署命令进入真实槽的服控队列，部署完成后仍保持停服。

## 数据兼容

迁移 `037` 在已经正式上线的迁移 `036` 之上执行：

- 保留 `036` 的 `launcher.unbound_activity_plans` 原始定义和校验和不变；
- 为企划新增 `activity_target_server_id` 外键，并为未绑定草稿新增可选
  `target_server_id`；
- 根据既有整合包部署计划回填真实承载槽，但只接受 owl5 的合法固定 `activity` 或
  `Ready` 独立槽；不会把 `survival2` 等普通固定服误作活动承载槽。无法解析时只回退
  合法固定 `activity`；任何既有企划仍无法得到真实槽时整笔迁移失败，不留下半迁移状态；
- 安装可信扩展 `btree_gist`，把全局时间排斥改为“承载服务器 ID + 时间区间”的复合
  GiST 排斥约束；
- 保持既有 `client_profile_id`、Minecraft 版本、加载器和活动整合包外键非空，不放宽旧
  玩家目录合同。

API `0.38.3` 可以在紧急情况下读取迁移后的数据库，但不理解真实承载槽语义，普通目录和
玩家目录会重新出现重复项。因此回滚只用于短时恢复，期间冻结企划与目录写入；数据库
迁移不向下删除，恢复 `0.38.4` 后重新启用完整行为。

  必须先保存并取得新修订号，部署按钮才会重新启用；

## 部署与回滚

部署前备份 PostgreSQL、API 环境、systemd 单元和当前发布指针。使用
`deploy/linux/install-release.sh` 原子切换，只重启 `hechao-launcher-api.service`；就绪
检查失败时自动切回 `0.38.3-20260904T035059Z`。本版不修改 Publisher、Nginx、Velocity、
服控代理，也不启动、停止或重启任何 Minecraft 服务端。

生产验收必须覆盖：迁移 `37/37`、`btree_gist` 已安装、普通后台只显示真实商业街槽、
活动企划显示逻辑企划及其绑定、玩家目录不重复、Velocity 返回
`minigame-commercial-street / 25602`，以及 Minecraft、Velocity、Publisher 和服控代理
PID 未变化。
