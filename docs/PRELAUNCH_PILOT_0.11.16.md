# 启动器 0.11.16 小范围测试手册

> 范围：管理员本机与 2 至 3 名内部玩家
>
> 目标：验证游戏退出状态修复，并回归登录、安装、修复、回滚、诊断上传与真实转服
>
> owl9 边界：本手册中的历史写法 `PVP` / `pvp` 均指恐怖整蛊 Fabric 服
> `C:\mc\server`。真正 PVP Purpur 服位于 `E:\MinecraftServer`，不在本轮测试中，
> 不得启动、停止或改动。

## 当前前置门槛

2026-07-28 的生产只读审计显示，目前只有 1 个社区账号绑定 Minecraft，尚不满足
2 至 3 人真实灰度条件。开始多人手册前必须先完成：

- 准备至少 2 至 3 个真实 Microsoft/Minecraft 正版账号并完成赫朝绑定；
- 确认目标服务已由管理员开启，目录状态与真实运行状态一致；
- 完成恐怖整蛊隔离链的真实 `/hub`、返回大厅、重新签发授权、再次进入恐怖整蛊和成功重连；
- 核对恐怖整蛊与大厅间 UUID、皮肤、LuckPerms 权限、命令树和玩家背包；
- 从启动器创建新的管理员后台票据，完成 MFA 后打开运行数据、服务状态与告警页面；
- 保留当前安装包和 `0.11.15` 回滚安装包的文件大小及 SHA-256。

完整门槛快照见
[`PRODUCTION_ACCEPTANCE_GATES_2026-07-28.md`](PRODUCTION_ACCEPTANCE_GATES_2026-07-28.md)。

## 安装前

- 只使用管理员提供的私有短时链接。
- 文件名必须为 `Hechao-Launcher-Setup-0.11.16-win-x64.exe`。
- 文件大小必须为 `61,866,222` 字节。
- SHA-256 必须为
  `6D7C9E91EA621B384633F86D6498EBBD55BF73B65516D8F24F0838CD48EA4D8A`。
- 可以直接覆盖 `0.11.15`，不要删除客户端、Java 或游戏数据目录。
- 安装包未做 Authenticode 签名；只接受上述文件名、大小和 SHA-256。

## 必测流程

1. 覆盖安装后确认版本显示 `0.11.16`，赫朝账号、Minecraft 绑定、设置、
   已安装档案、受管 Java 与玩家存档保留。
2. 启动并正常退出一个 Minecraft，确认当前档案从“游戏已启动”恢复为“游戏已退出”，
   进入服务器按钮重新可用；异常退出时显示“游戏异常退出”且启动器不退出。
3. 在旧进程退出事件可能延迟到达时重新启动同一档案，确认旧事件不会把新进程标成
   已退出。
4. 对基础、Activity 和恐怖整蛊档案各执行一次启动准备；确认 Mojang 日志配置缺失或
   损坏时自动恢复，启动器保持响应。
5. 分别完成 Lobby、Survival、Activity 和恐怖整蛊的代理路由；核对服务端 UUID、
   等级、兼容 NPC/命令转服、断线重连和正常退出。
6. 在隔离链完成恐怖整蛊 `1.20.1 -> /hub -> Lobby 1.21.11 -> 恐怖整蛊 1.20.1`
   往返；每次进入恐怖整蛊都使用新的短时授权，并保存 Velocity、恐怖整蛊与大厅三端日志。
7. 登录失败、取消登录、选错 Microsoft 账号、网络中断和游戏异常退出时，启动器
   必须保持运行并显示可重试状态。
8. 分别回归一次安装或修复、一次主动回滚和一次真实游戏启动；中断下载后继续，
   确认从已有分片续传。
9. 以自动 Java 启动 Java 21 与 Java 17 档案各一次，再为单个档案选择自定义 Java，
   确认互不串用。
10. 生成脱敏诊断包并主动确认上传；取消、网络失败和文件被修改时都不得退出启动器。
11. 管理员登记 MFA 后核对运行数据中的版本、事件结果和失败分类，并下载诊断编号、
   核对下载审计。

## 通过条件

- 正常和异常退出都能及时刷新当前档案，快速重启不会被旧退出事件覆盖。
- 登录失败、取消登录、检查失败、安装失败和上传失败均不会退出启动器。
- 全新安装与 `0.11.15` 覆盖升级不清除账号、设置、客户端或玩家数据。
- Activity 与恐怖整蛊的正确档案和身份转发均有真实日志证据；兼容返回路径和重连也必须
  分别留有真实日志。
- 自动 Java、修复、回滚和真实启动至少各完成一次。
- 本轮无阻断问题后才能进入 5 人灰度；5 人通过后再进入 20 人灰度。
