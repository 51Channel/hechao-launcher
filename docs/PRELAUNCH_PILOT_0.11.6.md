## 3. 必测流程

每名测试者从私有链接下载，不互相转传旧文件，并先核对 SHA-256。

| 阶段 | 操作 | 通过标准 |
| --- | --- | --- |
| 安装 | 全新安装；已有旧版者再做一次覆盖升级 | 启动器可打开，设置和既有游戏数据不丢失 |
| 赫朝账号 | 登录、错误密码、退出后重开、退出所有设备 | 错误只显示在页面，不闪退；有效会话可以恢复 |
| Microsoft | 正常绑定、取消浏览器授权、失败后重试 | 不收集 Microsoft 密码；取消或失败不退出启动器 |
| 基础客户端 | 安装 `base-1.21.11`，中断一次后继续 | 断点续传有效，进度持续前进，最终 SHA-256 校验通过 |
| 修复 | 人工改坏一个非玩家数据文件后执行修复 | 文件被恢复，世界、截图、设置等可写数据不被删除 |
| 启动 | 进入大厅，再进入可用生存服，最后使用 `/hub` | 选服、正版身份、代理转发和返回大厅都正常 |
| 状态 | 在服务关闭或维护时刷新目录 | 状态和按钮不可误导，不允许进入关闭服 |
| 退出 | 正常退出一次，再模拟一次异常退出 | 启动器不跟随游戏崩溃；本地退出记录和脱敏诊断可用 |

若 Activity 或 PVP 没有由管理员明确开启，本轮只验证它们显示“关闭”，不为测试
擅自启动服务器。

## 4. 观察项

- 安装包下载耗时、基础客户端实际平均速度和是否出现长时间零速。
- CPU、内存、磁盘占用以及剩余空间不足时的提示。
- 登录、下载、修复和启动按钮是否会重复触发任务。
- 登录失败、浏览器取消、网络断开、API 短时不可用时是否保持启动器进程。
- 大厅、NPC 转服、`/hub`、断线重连和重复进服。
- Velocity 日志中的 monitor 拒绝原因；monitor 只记录，不应踢出玩家。

问题记录至少包含：发生时间、启动器版本、所选服务器、操作步骤、页面提示和脱敏
诊断包。不要提交密码、Microsoft 令牌、浏览器地址栏或签名下载地址。

## 5. 停止条件

出现以下任一情况，停止扩大测试并保留现场：

- 安装包或档案 SHA-256 不一致。
- 登录失败或安装客户端导致启动器退出。
- 普通成员进入了不应访问的 Participant 服务器。
- 目录显示在线但 Velocity 实际目标不可用。
- 修复或升级删除玩家世界、截图、设置或账号数据。
- `hechao.world`、旧中转 API、Velocity 或现有 Minecraft 服务受到影响。

## 6. 本轮不做

- 不启用 `Authentication__EnforceCatalogAuthentication=true`。
- 不把 Velocity 改为 `enforce`。
- 不公开发布安装包或永久下载地址。
- 不在没有维护窗口时重启任何游戏服务。
- 不把管理员 Web 视为已验收；服主仍需完成首次 TOTP 和恢复码保存。
- 不把夹具测试写成生产世界备份已验收；首次正式 ZIP、SHA-256 和恢复演练仍待完成。

## 7. 扩大条件

2 至 3 人完成全部必测流程且没有阻断问题后，才进入 5 人灰度。5 人灰度至少包含
普通成员和活动成员。真实四级账号、NPC、`/hub`、断线重连和 API 故障路径通过后，
另开维护窗口把 Velocity 切到 `enforce`；其验收完成后再启用目录强制登录。
