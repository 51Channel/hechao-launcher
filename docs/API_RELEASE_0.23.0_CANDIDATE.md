## 0. 验收失败与回滚

候选部署后程序健康检查正常，但生产数据库仍停在迁移 `019`。根因是
`020_server_control.sql` 已嵌入程序集，`DatabaseMigrator` 的显式注册表却漏加第
20 项；当时的测试只检查 SQL 资源存在，没有核对全部嵌入资源都已注册。

发现后没有启用服控、没有发布启动器更新元数据，也没有操作任何 Minecraft 或
Velocity 进程。API 已原子切回 `0.22.0-20260729T144953Z`，就绪状态和数据库迁移
`019` 均恢复确认。修复增加连续注册表测试并升版为 `0.23.1`，本归档不得再次部署。

## 1. 变更

- 迁移 `020` 增加服控目标、操作、命令、代理心跳和必要索引。
- 管理后台增加第九个“服控面板”：
  - 结构化启动、停止与重启；
  - 冲突组先停后启，任一停止失败时取消目标启动；
  - 五项 `server.properties` 白名单快捷设置；
  - 命令前缀白名单约束的 Minecraft 控制台；
  - 操作状态、步骤、失败代码和审计记录。
- 管理动作要求已完成 MFA 的管理员会话、CSRF、完整服务器 ID 二次确认和操作原因。
- 代理接口使用每台主机独立的高熵令牌；API 只配置 SHA-256。
- `ServerControl__Enabled` 默认是 `false`。部署候选和执行迁移不会启动、停止或重启
  Minecraft、Velocity 或 Java 进程。
- 保留启动器更新元数据端点，为启动器 `0.13.0` 自更新提供已认证的私有对象地址。

## 4. 部署门槛

1. 创建 PostgreSQL custom-format 一致性备份、SHA-256，并确认
   `pg_restore --list` 可读。
2. 备份 API 环境文件、systemd 单元、当前发布链接与 Nginx 配置。
3. 上传临时归档并在远端复验 SHA-256。
4. 使用标准原子发布脚本切换，只允许重启 `hechao-launcher-api.service`。
5. 确认数据库连续迁移到 `020`，`healthz`、`readyz`、公开目录、认证、管理域名、
   论坛、中转 API 和公网 `8090` 边界均正常。
6. 明确核对 `ServerControl__Enabled=false`；不得部署代理或执行游戏服动作作为
   API 发布的附带步骤。
7. 只有两台 VPS 只读盘点和专用无玩家目标验收完成后，才另行启用服控。

## 5. 回滚

程序直接回滚目标为 `0.22.0-20260729T144953Z`。迁移 `020` 是兼容性加表和索引，
旧程序不读取新增表，回滚时优先保留数据库现状并只切回旧 API。出现任何服控异常时
先保持或恢复 `ServerControl__Enabled=false`；这不会结束当前游戏进程。
