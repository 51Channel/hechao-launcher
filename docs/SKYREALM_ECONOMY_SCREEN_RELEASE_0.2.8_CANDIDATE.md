## 本轮能力

“天域远征”从交易展示页进一步收口为 14 项快捷操作菜单：

- 交易：个人账户、回收目录、玩家市场、市场上架、我的挂单、待领取、玩家转账；
- 社交：我的队伍、玩家传送；
- 生存快捷操作：返回家园、返回主城、返回上次位置、我的领地、个人设置。

玩家转账新增原生输入表单，校验正版玩家名和最多两位小数的正金额，并要求在短确认窗口内
再次点击后才发送固定命令。玩家传送新增发起 TPA、邀请对方、接受和拒绝四个固定动作。
客户端不直接修改余额、物品、权限或传送结果，最终状态仍由 HechaoEconomy、
SkyrealmCore 和服务端命令树裁决。

## 会话与结果安全

- 客户端表单在收到服务端授权前不可输入或提交；
- 授权与拒绝回执同时绑定菜单会话 UUID 和动作 ID，旧会话的延迟消息不能解锁新表单；
- 内部会话回执在客户端消费后不进入聊天或 ActionBar；
- 转账只接收 `/pay` 的真实成功、失败和经济网关错误，不把余额同步、市场购买或公告误判为结果；
- 传送按“发起请求、邀请玩家、接受、拒绝”四类分别匹配 SkyrealmCore 真实回执；
- 等待服务端结果期间禁用输入、动作、返回和 Esc；
- 超时进入“结果未知”，禁止重复提交，只允许返回首页核对真实余额或传送状态；
- `240 x 100` 紧凑布局仍保留至少 `16 px` 状态区，错误和未知状态不会被页脚遮挡。

## 协议兼容边界

Screen `0.2.1` 与 `0.2.7` 使用网络协议 `2`。0.2.8 将协议升为 `3`，避免新客户端与旧
服务端静默混连后出现按钮缺失、表单无法授权或结果串线。因此发布顺序必须是同一受控窗口：

1. 确认 `activity-survival` 已正常保存并停止；
2. 备份并离线替换服务端 Screen 为 `0.2.8`；
3. 冷启动并验收协议、唯一 JAR、命令、日志和监听；
4. 再把客户端档案 `1.0.27` 切到 Test；
5. 使用两个真人账号完成菜单、转账、TPA 和既有交易链路验收。

服务端无法冷更新时，可以先完成不可变客户端制品与 OSS 上传，但不得提前切换 Test。
