# 赫朝启动器 API 0.38.3 活动企划后绑定客户端候选

> 候选日期：`2026-09-04`
> 状态：已于 `2026-09-04` 正式部署；正式记录见
> [`API_RELEASE_0.38.3.md`](API_RELEASE_0.38.3.md)

## 目标

管理员可以先创建活动企划，之后再导入并绑定客户端整合包。企划名称、公告、开放时间、
结束时间、人数上限和最低称号不再依赖客户端预先存在。

## 行为边界

- 新企划默认允许选择“稍后绑定客户端”，保存后为未绑定 `Draft`；
- 未绑定企划允许编辑、归档和恢复，不允许发布或部署；API 返回明确的
  `409 package_binding_required`；
- 绑定已完成且未归档的整合包后，在同一数据库事务内保留企划 ID、创建时间并递增修订号；
- 已绑定企划不能解除绑定，仍可按现有规则改绑其他有效整合包；
- 只有绑定客户端且精确清单进入 `Production` 的企划可以发布；
- 玩家启动器目录继续只读取 `launcher.servers` 中已发布记录，未绑定草稿不会泄露给玩家。

## 数据兼容

迁移 `036` 只新增 `launcher.unbound_activity_plans`，其状态约束仅允许 `Draft` 和
`Archived`。既有 `launcher.servers.client_profile_id`、Minecraft 版本、加载器和活动整合包
外键继续保持非空，不放宽旧目录合同。

因此程序回滚到 API `0.38.2` 时，未绑定草稿只会暂时不显示；数据仍保留在独立表中，重新
部署 `0.38.3` 后恢复可见。已绑定企划继续由旧 API 正常读取。数据库迁移不做向下回退。

## 部署与回滚

部署前备份 PostgreSQL、API 环境、systemd 单元和当前发布指针。使用
`deploy/linux/install-release.sh` 原子切换，只重启 `hechao-launcher-api.service`；就绪检查
失败时切回 `0.38.2-20260904T013112Z`。本版不修改 Publisher、Nginx、Velocity、服控代理，
也不启动、停止或重启任何 Minecraft 服务端。

生产验收必须覆盖：迁移 `36/36`、既有商业街记录不变、创建未绑定草稿、发布和部署拒绝、
归档与恢复、后续绑定、玩家目录无未绑定记录，以及 API `0.38.2` 对新数据库结构的只读
回滚兼容。验收产生的临时企划和审计测试数据应清理。
