# LuckPerms Tier Agent 0.1.3 候选发布

- 候选版本：`HechaoLuckPermsTierAgent 0.1.3`
- 配套 API：`0.30.3`
- 等级命令协议：`2`
- 数据库迁移：无
- 状态：源码和自动测试通过，尚未正式部署

## 复发根因

生产 `LobbyServer` 已加载 `0.1.2`，但历史 PVP 返回验收目录
`E:\Lobby-PvpReturn-Staging` 仍由计划任务运行，并加载 `0.1.0`。两个实例使用同一内部
同步凭据和 `agent-id=owl5-lobby`，会竞争领取真实命令。旧版按计算主组判断成功，只替换
继承节点而不保证 stored primary group，因此可返回 `Applied`，随后被五分钟只读快照恢复。

只读取证确认遗留实例不在 Velocity、服控或其他引用中，`25580` 没有已建立连接。已先
导出计划任务 XML 和无秘密状态清单，再禁用任务并停止进程；正式大厅、Velocity 与两个
生存服 PID 均未变化。该隔离操作没有修改玩家身份或数据库。

## 修复

- 代理领取和回执固定发送 `agentVersion=0.1.3`、`protocolVersion=2`；
- 启动日志同时显示代理 ID、软件版本和协议；
- API 在访问命令仓库前拒绝缺失、旧版或未知协议；
- 命令租约按 `agent-id@agent-version/protocol` 匹配，完成审计记录三项身份；
- 安装器目标 JAR 更新为不可覆盖的 `0.1.3` 文件名，继续保留原子替换和自动回滚。

## 部署顺序

1. 确认命令队列没有 `Pending` / `Claimed`，遗留计划任务仍为 `Disabled`；
2. 备份并安装 `0.1.3`，只优雅重启内部大厅；
3. 验证新启动日志、SQL messaging 和无新增代理错误；
4. 备份 PostgreSQL 与 API 环境，原子部署 API `0.30.3`；
5. 使用旧协议请求确认 `400`，协议 `2` 请求确认 `200`，队列仍为空；
6. 等待至少两轮五分钟同步，再用授权测试账号完成正向和恢复验收。

任何步骤失败都只回滚当前层。不得启动遗留 staging 任务，也不得操作 Velocity、生存服或
活动服。
