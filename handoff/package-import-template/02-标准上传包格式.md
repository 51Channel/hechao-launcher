# 标准上传包格式

## 1. 规范目录

最终上传 ZIP 解压后必须直接得到：

```text
hechao-pack.json
client/
  hechao-profile.json
  assets/
  libraries/
  versions/
  mods/                       按实际需要
  config/                     按实际需要
  resourcepacks/              按实际需要
server/
  server.properties
  eula.txt
  user_jvm_args.txt
  start.bat
  <服务端核心或加载器文件>
  mods/ 或 plugins/           由真实加载器决定
  config/                     按实际需要
  defaultconfigs/             按实际需要
  world/                      仅在明确随包交付地图时
shared/                       可选；为空时不要创建
  mods/                       仅放两端字节完全相同的共同 JAR
  config/                     仅放两端必须完全相同的配置
```

不要把上述内容再包进 `活动名/` 或 `.minecraft/`。平台虽然能识别部分外层目录，但本模板
只保证无外层包装的规范布局。

## 2. 根级 `hechao-pack.json`

字段：

| 字段 | 规则 |
| --- | --- |
| `schemaVersion` | 固定整数 `1` |
| `id` | 建议客户端档案 ID，2-64 位小写字母、数字、点、下划线、短横线 |
| `displayName` | 1-80 个可显示字符 |
| `version` | `major.minor.patch`，可带 SemVer 后缀 |
| `minecraftVersion` | 真实 Minecraft 版本 |
| `javaMajorVersion` | 与客户端元数据和服务端实际 Java 一致 |
| `loader` | 仅 `Vanilla`、`Paper`、`NeoForge`、`Fabric`、`Forge` |
| `loaderVersion` | 精确版本；Vanilla 也填写明确值，例如 `Vanilla` |
| `serverCore` | 可选但正式包应填写；仅 `Vanilla`、`Paper`、`Purpur`、`Fabric`、`Forge`、`NeoForge`、`Arclight`，且必须与 `start.bat` 实际启动核心一致 |
| `clientRoot` | 固定 `client` |
| `serverRoot` | 固定 `server` |
| `sharedRoot` | 固定 `shared` |

示例见 `templates/hechao-pack.json.example`。当前后台确认阶段不接受 `Quilt` 或
`Purpur` 作为加载器枚举；不要因为识别器能显示名称就假定可以发布。

`serverCore` 与 `loader` 描述的不是同一层。比如 Arclight NeoForge 服务端仍使用
`loader=NeoForge`，同时声明 `serverCore=Arclight`。省略该字段可兼容旧包，但部署检查
会要求人工复核；新正式包应显式声明。

`id` 是后台建议值，不是临时文件名。以下情况应创建新 ID：

- Minecraft 主版本变化；
- Vanilla、Paper、NeoForge、Fabric、Forge 之间切换；
- 独立模组集合或活动产品需要隔离可写 `.minecraft`。

同一活动、同一运行时和同一模组集合的兼容修复沿用 ID，只提高 `version`。

## 3. 文件归属

- `client/` 前缀在拆包后移除，文件直接成为启动器档案 `.minecraft` 内容。
- `server/` 前缀在拆包后移除，文件直接成为活动服务端目录内容。
- `shared/` 前缀在拆包后移除，并把同一字节分别写入客户端和服务端。
- 根级描述文件不会进入任一运行目录。

若 `client/mods/a.jar` 与 `shared/mods/a.jar` 同时存在，归一化后路径冲突，导入会阻断。
Windows 下仅大小写不同的路径同样冲突。

## 4. 不接受的交付

- 只有 `manifest.json` 和项目 ID 的 CurseForge 导出；
- 只有 `modrinth.index.json` 和远程 URL 的 MRPACK；
- 只有 mods/config、缺少版本 JAR、assets 或 libraries 的半成品客户端；
- 只有 world/mods、缺少服务端核心和启动脚本的半成品服务端；
- 客户端包和服务端包分成两个互不关联的 ZIP；后台当前接收一个双端归档；
- 包内包含凭据、生产配置备份、日志、数据库、账号缓存或符号链接；
- 使用示例 ID、示例版本或 `.example` 文件生成的包。

## 5. 平台硬边界

- 上传文件名 5-180 字符，扩展名 `.zip` 或 `.mrpack`；本模板生成 `.zip`。
- 当前默认上传上限 4 GiB，最多 50,000 个归档条目，展开后最多 20 GiB，单文件最多
  4 GiB，路径最长 400 字符。生产配置可能变化，上传前仍要实时核验。
- 元数据 JSON 小于等于 1 MiB，不允许注释和尾随逗号。
- 路径不能绝对化、穿越、重复、使用 Windows 设备名或符号链接。
- 上传完成并不等于可发布；必须同时识别客户端和服务端且没有 `Blocking` 问题。
