# 客户端制作规范

## 1. 客户端必须闭合

`client/` 是一个完整的、可独立安装的 `.minecraft` 根，不是覆盖补丁。至少包含：

```text
client/hechao-profile.json
client/versions/<versionId>/<versionId>.json
client/versions/<versionId>/<versionId>.jar
client/assets/indexes/<asset-index>.json
client/assets/objects/...
client/libraries/...
```

根据活动再加入：

```text
client/mods/...
client/config/...
client/defaultconfigs/...
client/resourcepacks/...
client/shaderpacks/...
client/kubejs/...
```

启动器会从签名清单安装这些文件，不会根据 CurseForge/Modrinth 项目 ID 在线补齐依赖。
Java 运行时由启动器按 `javaMajorVersion` 单独准备，不能把 `runtime/` 或本机 Java 打入包。

## 2. `hechao-profile.json`

该文件位于 `client/` 根，示例见 `templates/hechao-profile.json.example`：

```json
{
  "schemaVersion": 1,
  "versionId": "1.21.11-NeoForge_21.11.42",
  "javaMajorVersion": 21
}
```

必须满足：

- `versionId` 与 `client/versions/` 下真实目录和两个同名文件完全一致；
- 对应版本 JSON 的 `id` 等于 `versionId`；
- 对应版本 JSON 的 `javaVersion.majorVersion` 等于 `javaMajorVersion`；
- Java 主版本与根级 `hechao-pack.json` 一致。

## 3. 数据清理

不得进入客户端：

- `saves/`、`logs/`、`crash-reports/`、`screenshots/`、`debug/`；
- `launcher_profiles.json`、`launcher_accounts.json`、`servers.dat`、账号或皮肤缓存；
- PCL/HMCL 启动器状态、下载缓存、natives、Java runtime；
- `.hechao/`、`.hechao-install.json`、`.git/` 和构建目录；
- 访问令牌、Cookie、密码、私钥、`.env` 或包含生产地址凭据的配置。

`options.txt` 可以作为首次安装默认值，但启动器更新时会保留玩家现有文件。不要把开发者
自己的账号、按键、设备、语音音量或服务器列表当成默认配置。

## 4. 模组归属

- 纯客户端 UI、渲染、输入、性能和声音模组放 `client/mods/`。
- 服务端不应加载的客户端类不能进入 `shared/`。
- 两端共同活动 JAR 可放 `shared/mods/`，或分别放入两端并保证 SHA-256 一致；推荐
  `shared/`，因为平台会从同一字节生成两份载荷。
- 需要不同客户端/服务端配置时，分别放 `client/config/` 和 `server/config/`，不要用
  `shared/config/` 覆盖差异。

## 5. 验收

1. 在全新隔离目录安装客户端，不复用已有 libraries、assets 或 mods。
2. 启动器能读取 `hechao-profile.json` 并构建正确 Java 进程。
3. 游戏进入主菜单，无缺失类、Mixin、资源或加载器错误。
4. 使用测试服务端验证正确客户端能连接，错误档案清楚失败。
5. 重启、更新和删除档案后，不污染其他档案或玩家可写数据。
6. 记录客户端文件数、总字节、版本 ID、Java、共同 JAR 和最终 ZIP SHA-256。
