# 服务端制作规范

## 1. 服务端必须闭合

`server/` 解压后就是活动槽运行目录。必须包含：

```text
server/server.properties
server/eula.txt
server/user_jvm_args.txt
server/start.bat
server/<核心或加载器运行文件>
server/mods/ 或 server/plugins/
server/config/
```

所有加载器库、服务端核心、活动模组、指标/forwarding 后端组件和配置都必须来自已审查的
组件计划。不要从旧服整目录复制 `plugins/mods/config`。

## 2. 固定部署契约

当前自动导入只部署到：

```text
serverId       activity
agentId        owl5
backend        127.0.0.1:25568
velocityTarget activity
conflictGroup  owl5-activity-slot
```

代理在部署时强制把 `server.properties` 更新为：

```properties
server-ip=127.0.0.1
server-port=25568
online-mode=false
```

源包也应提前写成这些值，以便本地测试与生产拓扑一致。`max-players` 应为真实目标人数。
`online-mode=false` 只适用于受限回环后端；公网入口仍由正版登录的 Velocity 管理。

## 3. `start.bat`

服务端根必须有真正可运行的 `start.bat`，且单独包含以下一行：

```bat
if not defined HECHAO_MANAGED_START pause
```

文件还必须引用 `user_jvm_args.txt`，并使用相对路径启动当前目录里的真实加载器。不同加载器
示例见 `templates/start-scripts/`。选择一个示例后复制为 `server/start.bat`，再替换其中
版本和 JAR 名；不要把多个候选启动脚本一起当成正式入口。

Java 8 的 `java` 启动器不支持现代 `@user_jvm_args.txt` 语法。Minecraft 1.12.2 等旧
Forge 服务端应使用 `start.legacy-forge-java8.bat.example`，由批处理读取同一受管参数
文件后再调用根级 `forge-*.jar`。不要因此把 `-Xms/-Xmx` 复制回 `start.bat`。

不要使用绝对 Java 路径、裸 PowerShell 启动、`start` 派生脱离计划任务的进程，或在失败
后自动连接其他服务器。

## 4. `user_jvm_args.txt`

必须恰好包含一个 `-Xms` 和一个 `-Xmx`，例如：

```text
-Xms4096M
-Xmx8192M
```

后台提交的内存值会由代理原子重写。数值必须为 256 MiB 整数倍、`Xms <= Xmx`，且不超过
活动主机实时允许范围。其余 GC 参数必须针对实际 Java 和服务端验证，不能照搬旧服。

## 5. 主机管理文件与世界

- `forwarding.secret` 不属于上传包。它由 owl5 主机受控快照保留并注入。
- 世界目录只有在明确交付地图时才放入包。更新现有企划时，后台“保留世界”会用旧世界
  覆盖新包中的同名世界目录。
- 空活动槽部署时不能选择“保留世界”；不存在旧目录时没有可迁移的世界。
- 地图应移除无关玩家缓存和测试数据，保留玩法需要的数据，并记录来源、许可证和回滚
  备份。
- 日志、崩溃报告、备份、缓存和运行时 PID 文件不进入包。

## 6. 加载器边界

- `Paper` 使用 `plugins/` 和核心原生 Velocity modern forwarding 设置；根级加载器字段写
  `Paper`，不是 `Purpur`。
- `Fabric`、`Forge`、`NeoForge` 使用 `mods/`，不能加载 Bukkit 插件。
- Forge 1.12.2 等旧版可以使用唯一根级 `forge-*.jar`；现代 Forge 使用加载器生成的
  `libraries/net/minecraftforge/forge/.../win_args.txt`。两种形式都必须真实冷启动验证。
- Vanilla 当前缺少既有 modern forwarding 与指标基线，采用获批方案前不能进入生产。
- 每个 forwarding 和指标实现必须与精确 Minecraft/加载器版本兼容；不兼容时阻断生产，
  不能强装近似版本。
- Velocity Authorizer 只存在于 Velocity，Lobby Guard 和 LuckPerms Tier Agent 只存在于
  内部大厅，ServerControlAgent 和 StatusCollector 是 VPS 主机服务，均不复制进后端。

## 7. 专用服务端验收

1. 从空目录解压 `server/` 内容，在无图形模式启动。
2. 核对 Minecraft、加载器、Java、活动 JAR 和配置版本。
3. 核对只监听 `127.0.0.1:25568`，公网不能直连。
4. 验证正确客户端、错误客户端、无权限玩家和一次性授权。
5. 验证 `list`、保存、白名单、优雅停服、日志和世界落盘。
6. 采集 TPS/MSPT/GC、CPU、内存和磁盘；完成目标人数灰度。
7. 安全停服后再制作最终 ZIP。部署本身不会替你停止测试进程。
