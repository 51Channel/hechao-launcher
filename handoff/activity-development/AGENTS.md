# 赫朝活动开发交接包指令

本文件适用于解压后的整个交接包。实际活动源码仓库中更具体的 `AGENTS.md` 同时生效；
当前用户的明确要求和实时验证结果优先。

## 开始任务

1. 先读 `00-从这里开始.md`、`03-如何基于现有框架开发.md` 和
   `docs/ACTIVITY_CHANNEL_DEVELOPMENT_STANDARD.md`。
2. 再读 `docs/examples/ACTIVITY_CHANNEL_MINIMAL_CASE.md`，确认自己理解客户端档案、
   活动后端、目录记录、Velocity 目标和发布通道不是同一个概念。
3. 找到实际活动源码仓库后，在那里运行 `git status --short --branch`，读取其
   `AGENTS.md` 和构建文件。交接包是只读参考，不是活动源码仓库。
4. 路径、版本、端口、进程、计划任务、服务器状态和备份属于易变事实，写操作前实时
   核验；不要照抄历史证据。
5. 所有 PowerShell 业务脚本使用 PowerShell 7（`pwsh`）。

## 强制活动边界

- 玩家活动的 `velocityTarget` 固定为 `activity`。
- 当前活动物理槽为 owl5 回环 `127.0.0.1:25568`，冲突组固定
  `owl5-activity-slot`；同一时刻只允许一个后端。
- 不得把新活动接到 `survival2`、`lobby`、`pvp` 或其他玩家服。
- 历史 `dollnight -> survival2` 只是待迁移旧状态，不是模板。
- 不同 Minecraft 版本、加载器或独立模组集合使用不同 `profileId` 和可写
  `.minecraft`；同一活动兼容修复才沿用档案并升版。
- 正常新增活动由活动源码、签名客户端档案、服务端控制目标和后台目录驱动，不在启动器
  中硬编码每个活动卡片。
- 启动器是唯一换服入口。不得新增 `/hub`、NPC 换服、自动回大厅或失败回退。
- 服务端对角色、胜负、位置、物资、复活、救援、冷却和次数拥有最终权威。
- 原生 NeoForge/Fabric 不能加载 Bukkit 插件；不得未经批准采用混合核心。

## 实施规则

- 先写玩法状态机和失败条件，再写 UI 或网络包。
- C2S 只表达玩家意图；服务端验证身份、回合、状态、距离、频率、序号和权限。
- Minecraft 世界、实体、区块、库存、计分板和传送只能在服务端线程读写。后台线程只做
  有界 I/O 或不可变快照上的纯计算，结果回到服务端线程应用。
- 不通过缩小玩法半径、减少人数或偷偷修改规则掩盖性能问题。
- 变更地图、模组、插件或配置前先备份并验证回滚点。
- 部署默认以停止状态结束。除非当前任务明确授权，否则不启动、重启或切换生产服务端。
- 不执行含 `<占位符>`、示例 ID 或示例路径的命令。

## 安全与 Git

- 不读取、回显、保存或提交密码、密钥、令牌、Cookie、验证码和身份材料。
- 不提交构建目录、世界、日志、诊断包、数据库或生产包。
- 不回退或混入他人的工作；每项功能形成范围清楚、可回滚的 Git 提交并推送。
- 已发布对象、清单和标签不可覆盖，修复使用更高版本。

## 完成标准

完成报告必须包含源码提交、测试、客户端档案与清单 SHA-256、服务端目标、活动路由、
备份、是否启动、TPS/MSPT/GC、灰度人数、回滚路径和仍未完成的真人验收。不能用
“代码已写”“命令已发送”或“服务已启动”替代真实闭环。
